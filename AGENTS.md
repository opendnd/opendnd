# AGENTS.md

Contributor and agent guide for the OpenDnD monorepo. `CLAUDE.md` is a generated pointer to this file.

## What this is

OpenDnD is an open ontology, headless event-driven API and toolset for building fictional worlds. It is a project of OpenHI, a 501(c)(3), and the first non-healthcare consumer of the OURS ontology format. Read the docs site (`cd docs && bun run dev`) before changing architecture; decisions live in `docs/src/content/docs/adr/`.

## Layout

| Folder | Purpose |
|---|---|
| `/docs` | The single Starlight docs site: research, ADRs, guides, package docs. |
| `/packages/@opendnd/<name>` | Shared libraries. |
| `/apps/@opendnd/<name>` | Deployables: the API, generation workers, CDK stacks, desktop app. |
| `/sites/@opendnd/<name>` | Web front ends. The map, wiki, characters and campaigns are features of one application, not separate ones. |

Every sub-project is named `@opendnd/<name>` with a descriptive English name. Never hand-roll a sub-project: add it in `projenrc/packages.ts` (libraries and deployables) or `projenrc/sites.ts` (front ends) and run `bunx projen`.

## Tooling

- **Bun** is the package manager and test runner. **Turborepo** orchestrates tasks. **Projen** generates every config file.
- Never edit generated files (marked `~~ Generated by projen`). Edit `projenrc/*.ts` or `packages/@opendnd/projen`, then run `bunx projen`.
- Never `bun add` a dependency. Add it to `projenrc/packages.ts` (versions come from `packages/@opendnd/projen/src/versions.ts`) and run `bunx projen`, then `bun install`.
- Cross-package dependencies are `workspace:*` and resolve through built output; turbo builds dependencies before tests and before `generate`.
- Tests are Bun tests in each package's `specs/` directory, imported as `bun:test`. Use `__dirname`, not `import.meta.dir`; packages compile as CommonJS. Sites test with Vitest under jsdom instead, from the same `specs/` directory; `bun test` skips them.
- Inside a package's `src`, import across folders with relative paths (`../generator`). The `src/*` alias is for `specs` only: it survives into emitted declarations, where a consuming package would resolve it against its own `src` and silently get `any`. Sites bundle rather than emit declarations, so inside a site `@/` (its `src`) is allowed and is what the component library's generator writes.

## Commands

```bash
bun install && bunx projen   # install and regenerate config
bunx projen build            # build everything through turbo
bunx projen test             # lint, prettier check, all tests
bun run generate             # regenerate types, publish the OURS bundle and reference pages, write openapi.json
bun run dev                  # start apps and sites in dev mode
```

## Conventions

- The ontology in `packages/@opendnd/ontology/ours/` is the source of truth. `@opendnd/types` is generated from it and drift-checked; never edit `src/generated`. Regenerate with `bun run generate` at the repository root, never a package's own generate script, so the packages it reads are rebuilt first.
- A model schema declares `type: object`, extends `ResourceBase` through `allOf` and closes itself with `unevaluatedProperties: false`, never `additionalProperties: false`, which in draft 2020-12 would refuse the base's fields. A conformance test runs every schema through Ajv in strict mode.
- A model manifest's `relationships` name `Reference`-typed properties of its schema, dotted for nested ones; the validator refuses anything else. A model whose in-world span lives in its own fields declares them as `validTime` on its manifest. Every `$ref` is a canonical URL, and no schema uses an `x-` keyword.
- Fields the server sets (`id`, `model`, `world`, `recorded`, `module`) are `readOnly` in the schema and stripped from requests. Content is written through `Store`, never by inserting into `resource` directly, so every write has a version, a revision check and an event.
- The docs site's `reference/` pages, `public/ours/`, `public/.well-known/` and `public/openapi.json` are generated by `bun run generate` and ignored by git. Run it before building the docs; never edit them by hand.
- Generators live in `packages/@opendnd/generators/src/<name>/` and implement the `Generator` contract. They never call `Math.random`; they take the context's `Rng` and stamp output with provenance.
- Generators that call a language model implement `Author` instead, are asynchronous, and name a task (`chronicle`, `describe`, `author`, `review`, `embed`). Never choose a model in code: pass through the caller's choice, or leave it to the task's configuration.
- Every model call is priced and recorded. Any new path that calls a model goes through `Models`, or it is spend nobody is billed for.
- Postgres dialect everywhere (Docker locally, Neon in the cloud). Never introduce a second database engine. `docker compose up --detach --wait postgres` provides the local one; the API's test task does it for you.
- A world is the tenant. Content is reached through a world-scoped transaction (`inWorld`), and row-level security restricts it to the layers that world reads. Never widen a content query to work around it, and never serve as a database superuser or table owner: both bypass the policies.
- The API's route table comes from the ontology's model registry. Never name a model in the API.
- The application never names a model either. Its pages are built at run time from `/v1/models`, `/v1/openapi.json` and `/v1/vocabularies`; a model added to the ontology must appear in the application with no application change, and its specs use an invented model to keep it so.
- Components in a site come from shadcn/ui through its CLI, run inside the site (`bunx shadcn add <name>`). What it writes (`src/components/ui/`, `src/lib/utils.ts`, `src/hooks/use-mobile.ts`) is generated code: never edit it by hand, and the linters skip it. A dependency the CLI installs is moved into `versions.ts` and `projenrc/sites.ts`, then `bunx projen && bun install`.
- Sign-in in the application is `dev` under its development server and `cognito` in a build; the API decides whether `dev` is accepted (`OPENDND_DEV_AUTH=on`). Never make a build fall back to `dev` on its own.
- The deployment is CDK in `apps/@opendnd/infra`. There is no VPC and nothing charged by the hour; adding either needs an ADR. The API's function serves as `opendnd_app`, never the database owner.
- Code is MIT. The ontology ships shapes, not rules content: schemas may align to any published format, including ones whose data is OGL, because structure is interoperability and the licensed expression is the data. No rules content ships in this repository; it arrives as modules carrying their own licence. Test fixtures are invented; `CONTENT-LICENSE.md` carries the notice for any content that reproduces SRD material. No ORC or OGL material in the core corpus.
- ADRs are `docs/src/content/docs/adr/ADR-NNN-<slug>.md`, sequential, never date-based.
